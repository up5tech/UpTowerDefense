# 2026-10-26

## Phase 6 completed — tower roster, upgrades, status effects

Phase 6 was already mostly implemented in the working tree (three towers in
`towers.json`, upgrade/sell/priority domain + panel, splash and slow rules with
tests) but was never closed out. Finished it:

- **Fixed two real bugs from Phase 5 that made upgrades cosmetic:**
  - `LevelSession._combatStep` charged the cooldown from
    `tower.definition.fireCooldownSeconds` (base level) instead of
    `tower.stats.fireCooldownSeconds`, so fire rate never improved.
  - `TowerLayer` drew `tower.definition.range` instead of `tower.stats.range`,
    so the range circle lied after an upgrade.
- `CombatEvent` now carries the blast `radius`; `FxLayer` draws the real blast
  circle for a splash hit instead of a fixed dot.
- `EnemyLayer` marks slowed enemies with a frost ring plus three ticks (status
  is not conveyed by colour alone).
- Tower panel: current slow chip is now `Slow 40% / 2.5s`; the `Next:` line
  appends `blast N` / `slow M% / Ts` when the next level has those effects.
- Tests: +2 (`an upgraded tower fires on its new cooldown` via exact shot
  timings, `a single-target hit reports no blast radius`), plus blast-radius
  assertions on the splash tests and new panel-text expectations.
- Docs: added the missing D24–D27 rows to `GAME_DESIGN.md` §14 (the body text
  already linked to them), rewrote the stale Towers section of
  `CONTENT_AUTHORING.md` for the per-level schema, moved README/AGENTS phase
  status to Phase 6.

Gate: `flutter analyze` clean, 220 tests passing, `dart format` clean (101 files).

## Phase 7 completed — full level flow

- New `domain/level_phase.dart`: `LevelPhase { ready, playing, waveTransition,
  victory, defeat }` plus `LevelPhaseTransitions` (legal-move table). Every phase
  change goes through `LevelSession._enterPhase`, which asserts legality.
- `waveTransition`: a cleared wave holds `LevelDefinition.waveTransitionSeconds`
  (level data, default 5 s) and the next wave starts on its own; the same HUD
  control starts early. Countdown runs on simulation time, so pause freezes it
  and 2x runs it at double speed.
- Terminal phases clear the spawn queue and shots, and `advance` consumes
  nothing — late frames cannot move a finished level or pay twice.
- Pause/speed: `LevelController` owns the flag and the multiplier, scales the
  delta, and returns it so the game can feed the same value to `FxLayer`.
  `game.togglePause()` toggles controller + engine together; backgrounding never
  overrides a player pause.
- Restart: `LevelSession.restart()` resets every transient field in place;
  `game.restartLevel()` also clears `FxLayer` and the pad selection.
- Result summary: session now tracks `kills` and `goldEarned` in
  `reportEnemyDefeated`; `_ResultPanel` shows waves/core/kills/leaks/gold with
  Replay and Menu.
- Tests: new `test/unit/level_flow_test.dart` (14) and
  `test/widget/level_flow_test.dart` (5), plus controller pause/speed/restart,
  decoder and validation cases for `waveTransitionSeconds`.
- Docs: GAME_DESIGN §6/§8/§12 rewritten for the new flow, D28–D32 added and D16
  marked superseded; CONTENT_AUTHORING documents `waveTransitionSeconds`;
  README/AGENTS moved to Phase 7.

Gate: analyze clean, 247 tests passing, format clean (104 files).

## Phase 8 completed — campaign, progression, content gate

- New `features/campaign/`: `CampaignDefinition` (regions → ordered levels),
  `CampaignProgress` (best result per level, unlock = previous completed),
  `LevelRating` (3 = core untouched, 2 = at least half, 1 = finished, 0 = defeat),
  `CampaignValidator`, JSON decoder + repository, and Riverpod providers
  (`campaignProvider`, `campaignProgressProvider` Notifier).
- Content: 10 levels across 2 regions (`meadow_01..05` on `meadow_gate`,
  `ember_01..05` on the new `ember_pass` map), `brute` and `boss` enemies, and
  `assets/data/campaign.json` ordering them. The old single-level file
  `meadow_gate_01.json` is gone; a level id is now its file name.
- Routing: `/play` resumes the campaign's first unfinished level; `/play/:levelId`
  is a **sibling** route (not a child) so back from a level is one step to the
  menu. `levelBundleProvider` family loads by id.
- Level picker: regions with per-level number, name, stars or lock, totals, and a
  "session only" note until Phase 9 persists progress.
- Gameplay screen records the result once per finished attempt (listener on the
  controller, flag re-armed when the level is no longer over); the result panel
  now shows the star rating.
- `tool/validate_content.dart`: pure-Dart validator over every shipped asset plus
  campaign cross-checks (`dart run tool/validate_content.dart`).
- Tests: campaign decoder/validator/progress/rating, `campaign_assets_test`
  (campaign covers exactly the shipped level files, per-level playability gates,
  boss is the finale, real provider chain Play → next level), and the level
  picker widget tests. `pumpApp` now overrides the campaign providers with
  fixtures, because asset loading inside `pumpAndSettle` hangs.
- Docs: GAME_DESIGN §12/§13 + D33–D38, CONTENT_AUTHORING §Campaign + level steps,
  README/AGENTS to Phase 8 with the validator command.

Gate: analyze clean, 286 tests passing, format clean (116 files), content
